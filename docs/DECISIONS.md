# Decisions

This run was unattended, so every choice was made without asking. Each one is recorded here with
its reason. The owner decisions of 2026-11-25 (name, stack, accounts, health, AI, languages,
pictures, scale) are final and are not repeated as open questions.

| # | Decision | Reason |
|---|---|---|
| D-001 | Expo SDK 58 (latest), Expo Router, React Native Web, TypeScript strict. Routes in `src/app`. | Owner decision 2: one codebase for web, Android and iOS. SDK 58 is the current stable release. |
| D-002 | Web output `single` (an SPA), not static rendering. | Simplest offline PWA. Workers assets give an SPA fallback, and the service worker caches one shell. SEO is not a goal for a family app. |
| D-003 | A tiny in-house i18n (`src/i18n`), not i18next. | It is about 1 KB against 40 KB or more. All strings are in `locales/en.json`, `isRtl()` sets the document direction, and a unit test fails on any missing key. Hindi and Gujarati are later rounds. |
| D-004 | **One Worker** (`home-tutor`) serves both the PWA assets and `/api/*` (`run_worker_first` for `/api/*`), not two Workers. | Same origin: no CORS for the web, one deploy, one URL, fewer moving parts and lower cost. The brief's "API worker" and "web worker" are the same deployable. Splitting later is a config change. |
| D-005 | Sign-in uses email + password with a one-time recovery key, and **the email is stored only as a hash**. | There is no email service (owner decision 3). We never need to send to the address, so storing a hash is the minimum data. The trade-off: we can never contact users. |
| D-006 | Passwords use PBKDF2-SHA256 at 100,000 iterations. | This is the strongest setting WebCrypto allows in Workers (100k cap). Argon2 would need WASM and use more CPU per request. |
| D-007 | The parent PIN is a salted, iterated SHA-256 hash on the device, unlocked for 15 minutes in memory. | It keeps young children out of parent and tutor areas on a shared device. It is not account security, and it works offline on every platform (pure JS SHA-256, since Hermes has no `crypto.subtle`). |
| D-008 | Progress is an **append-only event log**; mutable records use last-writer-wins. | Offline devices then never conflict on progress (union of events), and family and child edits converge deterministically. The tests cover both cases. |
| D-009 | Progress Key snapshots are **built on the parent's device** and uploaded after sync. | The server then never needs the content catalogue or progress logic, and the snapshot holds only what the parent's app chose to share (first name, age, capabilities). The key code is stored as a hash. |
| D-010 | Progress Keys need a signed-in account; the printable passport works offline without one. | A key must be openable on someone else's device, which needs the cloud. Printing covers families without accounts. |
| D-011 | Health modules are four modules: `body-basics`, `growing-up-girl`, `growing-up-boy`, `adolescent-health`. All are OFF by default, shown only within their own age bands, and never shared in group lessons. | Owner decision 4 and brief section 22 mode D (health pathways stay private). Mode B/C set-up shows a note but still leaves the switch to the parent. |
| D-012 | Sex is asked only as "for health lessons only", with "prefer not to say". The girl module is hidden for boys and the boy module for girls; both are available for "prefer not to say". | Gender must only switch on health modules and never limit learning. A unit test checks that non-health visibility is identical for girls and boys. |
| D-013 | Birth is stored as **year and month** only. | Minimal data (COPPA/GDPR-K). Age bands and levels need no more. |
| D-014 | Levels 1-10 per subject start from an age default or a parent override, and rise when the child completes and passes items at or above their level. | Brief section 24: level is separate from age. It is simple, explainable and offline. |
| D-015 | Adult confirmation is required for the stages Can demonstrate, Can apply and Can teach, and for real-world evidence. | Brief section 27 and the passport's credibility. The child can record Knows and Understands on their own. |
| D-016 | Achievements are badges that are never lost. There are **no streaks** and no leaderboards. Daily screen-time limits are set per child, with a friendly off-screen page. | Brief section 34: avoid video-game addiction. Reward effort, curiosity, persistence, mastery, cooperation and real-world accomplishment. |
| D-017 | Today's plan is fixed for the day once it is made. | Otherwise finished items vanish and the plan reshuffles, which is confusing for children (found in e2e). |
| D-018 | Content is web-fetched per area and cached by the service worker. Native builds bundle all content. | Small first load on slow or expensive connections (owner decision 8). Native works with no network at all. |
| D-019 | Content was written by five parallel helper agents against a strict schema, then validated and reviewed. | The fastest way to cover 17 areas × 5 age bands in one round. The validator enforces the safety rules, so mistakes fail the build. |
| D-020 | Source URLs use organisation topic or home pages wherever the writer was unsure of a deep link. | A wrong deep link is worse than a stable topic page. Some links could not be fetched from the build sandbox (proxy blocks); see STATUS open questions. |
| D-021 | Emergency numbers are marked `verified: true` only when an official source documents them (43 of 66). The others show "unverified, check locally". | The brief says to mark any number we cannot verify. |
| D-022 | The mascot "Sprout" (a round seed-friend with a two-leaf sprout) is drawn with react-native-svg. App icons are rendered from the same SVG with Playwright. | Owner decision 7: no AI images; original art drawn in code. |
| D-023 | Default font is the system font. The dyslexia-friendly option uses Atkinson Hyperlegible (SIL OFL) with wider letter spacing and line height, downloaded only when switched on. | A zero-cost default and a recognised legibility font. OpenDyslexic has weaker evidence, and Atkinson also helps low vision. |
| D-024 | Read-aloud uses `expo-speech` (Web Speech API on the web). | Owner decision 7: free, on-device, offline on most devices. |
| D-025 | The worldview setting has three modes: comparative (default), family tradition first, and not now (hides lessons with subject worldviews, beliefs and practices, or festivals; philosophy and ethics stay). | Brief section 32: the parent picks the religious or worldview approach. Teaching stays comparative and neutral. |
| D-026 | Presentation mode is a projector context that scales type by 1.6. Lesson steps move with arrow keys, PageUp/Down or a TV remote, plus tap targets. Polls and class questions are local to the teacher's device in v1. | Mode H. Real multi-device voting needs realtime infrastructure (Durable Objects) and is deferred. |
| D-027 | Classroom groups, assignments and attendance are local and synced records; attendance and polls are device-local in v1. | This keeps v1 simple. Attendance sync is listed as next work. |
| D-028 | The local test server (`scripts/serve-dist.ts`) runs the **real** Worker API handler on Node's built-in SQLite through a D1-compatible shim. | The e2e tests exercise real auth, sync and keys without Cloudflare credentials. |
| D-029 | CI runs on GitHub Actions: validate → content → typecheck → unit → build → Playwright (4 viewports + axe). | The repo is public, so the minutes are free (owner decision 8). |
| D-030 | The D1 `database_id` in `wrangler.jsonc` is a zero placeholder. `scripts/deploy.sh` writes the real id into an untracked copy at deploy time. | Never commit account identifiers to the public repo. |
| D-031 | No licence file. The README says all rights reserved. | Owner decision 1. |
| D-032 | AI tutor: interface plus a 501 stub route plus a feature flag typed `false`. No UI. | Owner decision 5. |
| D-033 | Axe rule `scrollable-region-focusable` is disabled in e2e. | RN Web scroll views are divs without tabindex. All content inside is reachable by keyboard and is checked by the other rules. Revisit when adding a custom web ScrollView. |

## Round 2 (2026-11-25)

| # | Decision | Reason |
|---|---|---|
| D-034 | `scripts/deploy.sh` writes its temporary config to `wrangler.deploy.jsonc` **at the repo root** (gitignored, removed on exit), and checks `wrangler whoami` instead of requiring `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID`. | Wrangler resolves `main`, `assets.directory` and `migrations_dir` relative to the config file, so the old `.wrangler/deploy.jsonc` pointed into `.wrangler/`. Rewriting paths is fragile; a sibling file needs no rewriting. `whoami` works for both OAuth and token logins. |
| D-035 | E2E tests that sign up always delete their account in a `finally` block via `DELETE /api/account`; one test also presses the real Delete-my-account button. | Owner request: a live run must leave no data behind, even when a test fails half-way. |
| D-036 | Privacy contact is the public GitHub Issues page, with a warning not to post personal details there. | Owner decision. Never publish a personal email. |
| D-037 | Set-up defaults come from the device locale (`navigator.languages[0]`, then `Intl`): the region picks the country (unknown region: Other; no region: a likely country for the language), the language picks the UI language if we have it, else English. Both can be changed at set-up and in Family settings. New children inherit the family country and UI language. | Owner decision. "Other" is more honest than guessing a country we do not list. |
| D-038 | Tutor accounts are ordinary accounts linked to a parent account by a `tutor_links` row (migration 0002, additive). Invite codes are 12 characters, single-use, valid 7 days, stored only as a hash; after use the hash is replaced. | One account type keeps auth simple (a tutor can also have their own family). Hash-only, one-time codes match the Progress Key design. |
| D-039 | Tutors sync through `POST /api/tutor/links/:id/sync`, which reads only `child` and `event` records of the **shared, live** children of the parent account and never the family record (it holds the PIN hash). Tutor writes are limited to new events (stamped `by: 'tutor'` by the server) and six learning fields of a shared child (`levelOverrides`, `interests`, `goals`, `strengths`, `growingAreas`, `learningStyles`); deletes and all other kinds are rejected. | Owner decision: the tutor sees and updates only the shared children and cannot delete anything. Enforcing it field by field on the server means a modified client cannot change names, health settings or consent. |
| D-040 | Removing a tutor sets `removed_at`; the tutor's next request gets 403 and their device forgets that family. Deleting either account deletes its links. A newly shared child makes the tutor's device re-read from cursor 0. | Access ends at once, and nothing of the family stays on the tutor's device. Re-reading is the simplest correct way to receive the older history of a newly shared child. |
| D-041 | Tutored families live in a separate device store (`home-tutor:tutoring:v1`), cleared on sign-out, account deletion and device wipe. | A tutor's own family (if any) never mixes with the families they tutor. |
| D-042 | Hindi UI (`hi.json`, every key) was drafted by three parallel helper agents against strict rules (placeholders kept, तुम for children, आप for adults, everyday Hindi with common loanwords), then checked by a unit test. Non-English locales load as their own lazy chunk (`import()`), precached by the service worker. | Fast full coverage; the test fails on any missing, extra or placeholder-broken key and on untranslated values. Lazy chunks keep the entry bundle the same size however many languages are added. A native Hindi speaker should still review it (see STATUS). |
| D-043 | On the **web only**, `expo-router` is replaced by a ~200-line shim (`src/nav/expo-router.web.tsx`) via a Metro alias, with an explicit lazy route table (`src/nav/routes.web.ts`) and a web entry `index.web.js`. Android and iOS keep the real Expo Router (`index.js`). | Measured first: the entry was 1.1 MB raw / 291 KB gzip, of which Expo Router's runtime (React Navigation, tabs, toolbars, head manager, sitemap) was ~430 KB raw. Metro's experimental tree shaking saved only 4 KB, and stubbing Expo Router internals touched 20+ import sites. The app uses only push/replace/back/canGoBack, useLocalSearchParams, Stack and Slot, so a shim is small, testable and keeps every feature. Result: entry 163 KB gzip, everything on first load 182 KB. A unit test keeps the route table in step with `src/app`, and e2e covers back, forward, deep links and 404. |
| D-044 | CI runs `npm run check:bundle` after the web build: the scripts index.html loads must total under 200 KB gzip, and every lazy chunk under 60 KB. | Owner goal; a budget in CI stops the size creeping back. |
| D-045 | Attendance is synced as `attendance` records with id `groupId:day` and data `{ groupId, day, childIds }`, merged last-writer-wins like groups. Round-1 attendance on a device is given timestamps and queued on first load. Deleting a child also removes them from attendance days. Tutors cannot write attendance. | Records reuse the existing sync, so no schema change is needed (the `records` table is generic). One record per group per day keeps conflicts small and easy to reason about. |
| D-046 | The class report (`/classroom/report?group=`) is built on the device by a pure function (attendance, activities, group lessons, minutes, quiz average, adult-confirmed skills, areas) for 7, 30 or 90 days, and printed with the browser's print dialog. | Works offline and without an account, like the printable passport. It says plainly that it is not an official school report. |
| D-047 | Passkeys use `@simplewebauthn/server` 14.0.3 in the Worker and `@simplewebauthn/browser` 14.0.0 (lazy chunk) on the web, with migration 0003 (`passkeys`, `webauthn_challenges`). Discoverable credentials, attestation `none`, the relying party is the request host and the page origin must match it, challenges are single-use and expire in 5 minutes. The passkey's user name is "Home Tutor account" (no email). | Hand-written WebAuthn crypto is a security risk; this library is maintained, WebCrypto-based and runs on Workers. The Worker grows from about 23 KB to 137 KB gzip, far below the Workers limit. Password and recovery key keep working, so a lost phone never locks a family out. |
| D-048 | Passkeys are web-only in this round. | Native passkeys need associated domains / Digital Asset Links tied to the owner's Apple and Google developer accounts; the native app keeps email + password. |
| D-049 | Unit tests drive the passkey routes with a small software authenticator (real ES256 keys, hand-built CBOR); e2e uses Chromium's virtual authenticator. | Both test the real verification path without mocks. |
| D-050 | Exports use platform files: `download.web.ts` downloads a file; `download.native.ts` writes to the cache with `expo-file-system` and opens the system share sheet with `expo-sharing`, then deletes the cache file. The native print screen offers "Share passport file". | The share sheet is the native way to save to Files or Drive or send to oneself, and the app itself still uploads nothing. Checked by building the Android bundle (`expo export -p android`). |

## Round 3 (2026-11-25)

| # | Decision | Reason |
|---|---|---|
| D-051 | **Unlocked review edition** from the same code: `EXPO_PUBLIC_EDITION=unlocked` (build `npm run build:web:unlocked` into `dist-unlocked/`), deployed by `bash scripts/deploy.sh unlocked` as Worker `home-tutor-unlocked` with its **own** D1 database `home-tutor-unlocked` and `EDITION=unlocked`. In it: `visibilityFor()` opens every item (Amber/Red keep their adult flags), careers ignore age, there is no parent PIN, a ready-made review family (learners aged 4, 9 and 15, all health modules on) is created on first open, a banner shows on every screen, `/review` has Browse everything (area, age band, safety rating, type, search) and View as (ages 3-17, girl, boy or mixed group, health lessons on or off). View-as learners (`viewas-` ids) always get the normal gates (`strict`), so the panel shows exactly what a child gets in the normal edition. `index.html` gets `noindex, nofollow`, `robots.txt` disallows all and `_headers` adds `X-Robots-Tag`. Review-edition screens are English only. | Owner request. One codebase means the review always matches what families get; a separate Worker and database keep review data apart from real families. The flag is read through one module (`src/core/edition.ts`) so unit tests cover both editions. English only because it is the owner's checking tool and adding its strings to every locale would only create untranslated keys. |
| D-054 | E2E clean-up check: `testEmail()` writes every address to a run ledger (`.e2e-run/`, cleared by a setup project). A teardown project runs after all others and calls `POST /api/test/leftovers`, which returns only a count of accounts still present. The route accepts only addresses of the e2e shape on `example.org` (reserved by IANA), at most 100 per call and 30 calls per IP per hour. The passkey test now deletes its account with the session made by the passkey sign-in (round 2 used the signed-out token, got 401 and left the account). | Owner request: prove a live run leaves no account behind. Restricting the route to the reserved test domain means it cannot be used to discover whether a real family has an account. |
| D-055 | Gujarati UI (`gu.json`, every key) drafted by a helper agent (તું on child screens, તમે on parent screens, gender-neutral verb forms where Gujarati would force a gender, લિંગ not જાતિ for sex), registered as a lazy chunk like Hindi. Five values stay in English exactly where Hindi does (app name, Progress Key, Learning Passport, Auto). | Same pattern and tests as Hindi (D-042): the i18n test checks keys, placeholders and untranslated values for every locale. A native speaker should still review it. |
